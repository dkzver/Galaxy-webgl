# Архитектура генерации коллайдеров и физики

Документ фиксирует слои, которые появились после разбиения `collider-fit.js`
и `physics.js` на модули. Главное правило: **геометрия и физика не знают про
DOM и WebGL** и запускаются в Node.js через `node --test`.

## Слои

```
public/js/editor/collider/
  voxelizer.js        треугольники → воксели, заливка, sealGaps
  box-merger.js       жадное покрытие, слияние, bestGreedyCover
  box-collider.js     сборка боксов и статистика
  sphere-packer.js    сферы и hybrid
public/js/editor/collider-fit.js   публичный фасад + выбор/лучи

public/js/physics/
  shapes.js           формы, локальные части, мировые запросы
  narrowphase.js      сфера-бокс, бокс-бокс, сфера-сфера
  world.js            Body, PhysicsWorld, шаг симуляции
public/js/physics.js   фасад для старого кода и тестов
```

`public/js/physics.js` и `public/js/editor/collider-fit.js` сохраняют прежние
экспорты: сцены, редактор и тесты не переписываются.

## Генерация коллайдера

1. **Вокселизация.** Каждый треугольник растеризуется точным SAT-тестом
   «треугольник–воксель». Кандидаты берутся по AABB с запасом в одну ячейку,
   чтобы треугольник на границе задел обе соседние клетки.
2. **Заливка.** От границ сетки заливается внешнее пространство; всё, что не
   достигнуто, считается объёмом.
3. **`sealGaps`.** Для внешних вокселей считаются шесть осевых лучей. Если
   минимум пять упираются в поверхность не дальше `sealRadius` (по умолчанию
   3 ячейки), воксель закрывается. Ограничение длины луча — компромисс:
   микротрещина закрывается, широкий зазор между отдельными деталями — нет.
4. **Покрытие.** `coverSolid(grid, axisOrder)` умеет расти в любом порядке
   осей. `bestGreedyCover` перебирает шесть перестановок и выбирает минимум
   брусков, затем минимум объёма. Для редактора дополнительно выбирается
   вариант с лучшим заполнением **после** сокращения до лимита.
5. **Сокращение.** `mergeNeighbours` сливает только соприкасающиеся боксы и
   только при приемлемой доле пустого объёма. Если лимит всё равно превышен,
   сетка огрубляется и пересобирается.
6. **Сферы.** `buildSphereCollider` строит поле расстояний до внешнего
   пространства, затем жадно выбирает воксель с максимальным радиусом
   вписанной сферы и помечает покрытые клетки. Сферы подрезаются по габаритам модели.
7. **Hybrid.** Сначала крупные участки покрываются боксами, остаток —
   сферами; общий бюджет `boxes.length + spheres.length <= maxParts`.

## Узкая фаза

`_collide` перебирает части compound, но перед SAT проверяет описывающие
сферы:

- бокс-сфера: расстояние между мировыми центрами против
  `boxPart.boundingRadius + sphere.radius`;
- бокс-бокс: расстояние между центрами против суммы `boundingRadius`.

`boundingRadius` вычисляется при создании части в `boxShape`/`compoundShape`.
Для старых описаний без поля радиус считается по полуразмерам. Счётчик
`world.narrowphase` (`boxSphere`, `boxBox`, `culled`) позволяет проверять
отсечение в тестах.

## Редактор модели

В «Автоколлайдере» появился режим:

- `boxes` — `buildBoxCollider`;
- `spheres` — `buildSphereCollider`;
- `hybrid` — `buildCompoundCollider({ mode: 'hybrid' })`.

Результат раскладывается в `state.parts` как `kind: 'box'` / `kind: 'sphere'`,
попадает в предпросмотр, список частей и `public/models/<id>.physics.json`.
Статистика показывает режим, сетку, ячейку, число боксов/сфер и заполнение.

## VFX-подсистема

Эффекты — данные, а не зашитые рецепты:

- `public/effects/<id>.effect.json` — `params`-схема и слои (`smoke`, `spark`);
- `entity.effects` — слоты на любом объекте (`trigger`, `loop`, `duration`,
  `offset`, `scale`, `params`);
- `type: 'effect'` — самостоятельный узел дерева с трансформом и детьми;
- `EffectSystem` — старый покадровый API плюс пул инстансов, привязка к
  `entity.matrix`, `spawn/play/stop/setParams/isActive`, реестр layer handlers;
- `scene-runtime` запускает `auto` при сборке и `impact` по событию физики;
- `/api/effects` и `/api/effect/:id` отдают и сохраняют описания для редактора.

Слои расширяются через `registerLayerHandler(type, handler)`, поэтому новые
визуальные типы не требуют правок ядра. Старые `beam/tracer/rocket/smoke/spark`
сохранены без изменений.

## Снаряды из префабов

Ракета — сущность префаба, а не процедурный эффект:

- `public/js/prefabs.js` — чистые данные: клон дерева, новые id, трансформ,
  нормализация блока `projectile`. Модуль headless;
- `public/js/prefab-runtime.js` — `spawn(id, transform)` / `despawn(handle)`:
  `buildScene` собирает поддерево, `attachBodies` для снарядов пропускается;
- `public/js/projectiles.js` — полёт и попадания: шаг кадра дробится на
  подшаги не длиннее половины радиуса, свип сферы проверяется против
  `getWorldSpheres` / `getWorldBoxes`; попадание срабатывает один раз;
- `public/js/projectile-pool.js` — прогретые экземпляры: `acquire` показывает
  поддерево и включает след, `release` гасит эффекты и прячет;
- `EffectSystem.mount/unmount` — привязка поддерева без `autoplay`, поэтому
  спящие ракеты не дымят в точке прогрева.

Порядок кадра: `physics.step` → `scripts.update` (выстрел) →
`projectiles.update` (свип) → `updateScene` (матрицы) → `effects.update`.

Попадание отдаёт точке и нормаль, играет эффект `impact` и прикладывает
импульс к динамическому телу цели. Скорость и жизнь берутся из блока
`projectile` префаба, а параметры скрипта (`rocketSpeed`, `rocketLife`)
перекрывают их для конкретного выстрела.

## Совместимость и проверки

- Старые `*.scene.json` и `*.physics.json` читаются без изменений: новые поля
  (`boundingRadius`) живут только в рантайм-объектах форм.
- `npm test` включает `tests/collider-fit.test.mjs`, `tests/physics.test.mjs`,
  `tests/scene.test.mjs` и `tests/rocket-asset.test.mjs`.
- `node --check` прогоняется по всем модулям перед коммитом.
