# Сцены GalaxyDemo

Сцена — это JSON-файл. Код игры ничего не знает о конкретной сцене: он читает
`public/scenes/<id>.scene.json`, собирает сущности и запускает полёт.

## Как открыть сцену

```
http://localhost:3000/?scene=open-space     # открытый космос (по умолчанию)
http://localhost:3000/?scene=first-game     # своя сцена
http://localhost:3000/                      # сцена по умолчанию
```

Сцена — файл в `public/scenes`. Подходят два имени: `<id>.scene.json` или `<id>.json`
(например, `first-game.json` — это сцена `first-game`). Если лежат оба, берётся
`.scene.json`.

`public/scenes/index.json` задаёт порядок и подписи в списке редактора; сами
сцены редактор находит в папке. Запись в `index.json` без файла показывается
как «— нет файла» и не открывается — так сразу видно опечатку в id.

```json
{
  "scenes": [
    { "id": "first-game", "title": "Первая игра", "description": "Моя сцена" }
  ]
}
```

## Структура сцены

Корень сцены — объект `scene`. Он один, его нельзя удалить или создать заново, а все объекты
сцены лежат в его `children`.

```json
{
  "version": 1,
  "id": "first-game",
  "title": "Первая игра",
  "entities": [
    {
      "id": "scene",
      "type": "scene",
      "name": "Сцена",
      "scripts": [{
        "file": "first-screen.js",
        "params": {
          "background": "#02030a",
          "hudStyle": "hud/style.css",
          "loadingFile": "hud/loading.html",
          "loadingScript": "scripts/loading.js",
          "cursor": "reticle-cursor-1"
        }
      }],
      "player": { "model": "corinth" },
      "children": []
    }
  ]
}
```

| Поле | Что задаёт |
|------|------------|
| `version` | версия формата, сейчас `1` |
| `id` | имя файла без `.scene.json` |
| `title` | заголовок вкладки и меню |
| `entities[0].type` | всегда `scene` — корневой объект сцены |
| `scripts` | **обязательный** скрипт сцены (`first-screen.js` или свой); в `init` он вызывает `api.scene.build(...)`. Без скрипта или без вызова `build` игра не запускается |
| `player.model` | legacy-fallback модели игрока, если в сцене нет сущности игрока |
| `player.spawn` | legacy-ссылка на точку появления; рантайм её не использует |
| `children` | все объекты сцены: модели, HUD, камеры, триггеры и вложенные группы |

Старые поля `background`, `hud.style`, `loading`, `cursor` движок **не читает**:
он берёт только значения, переданные скриптом в `api.scene.build({ background,
hudStyle, loadingFile, loadingScript, cursor })`. Нет скрипта или нет вызова
`build` — игра не стартует и показывает ошибку.

## Сущность

Общие поля:

| Поле | По умолчанию | Смысл |
|------|--------------|-------|
| `id` | авто | уникальный идентификатор в сцене |
| `type` | по полям | `scene`, `model`, `primitive`, `empty`, `trigger`, `spawn`, `bot`, `hud`, `camera` |
| `name` | `id` | подпись в редакторе |
| `position` | `[0,0,0]` | координаты внутри родителя, у корневых — мировые |
| `rotation` | `[0,0,0]` | углы Эйлера в градусах, порядок X → Y → Z |
| `scale` | `1` | число или `[x,y,z]` |
| `spin` | — | постоянное вращение: число (рад/с вокруг Y) или `{ axis, speed }` |
| `visible` | `true` | `false` — объект и все его дети не участвуют в игре: нет меша, тела, скриптов и HUD-слоя; в редакторе остаётся в дереве |
| `tags` | `[]` | произвольные метки для скриптов |
| `hiddenParts` | `[]` | имена объектов или групп модели, которые не рисуются у этого объекта: так скрывают штатное оборудование и ставят своё |
| `materialId` | `null` | материал из `public/materials`: `shield` рисует прозрачную оболочку с пятном в точке попадания |
| `scripts` | `[]` | скрипты сущности (см. ниже) |
| `partScripts` | `{}` | скрипты на отдельные меши модели |
| `body` | — | физическое тело |
| `children` | `[]` | вложенные сущности, трансформ наследуется |

### `model` — готовая модель

```json
{
  "id": "asteroid1", "type": "model", "asset": "asteroid1",
  "position": [-30, 7, -96], "scale": 1.15, "spin": 0.035,
  "mining": { "zoneScale": 2 },
  "body": { "kind": "static", "collider": { "shape": "sphere", "radius": 9.36 } }
}
```

`asset` — имя файла в `public/models` (`<asset>.json` + `<asset>.mesh.bin`).
`mining` включает добычу: вокруг камня появляется зона радиусом
`radius × zoneScale`, а луч добычи считается по треугольникам меша.

#### Взаимодействие с мышью

У модели есть блок `mouse` — два независимых флажка. По умолчанию оба выключены:

```json
{
  "id": "station", "type": "model", "asset": "orbital-station",
  "mouse": { "hover": true, "click": false }
}
```

В редакторе это секция **«Взаимодействие с мышью»** в инспекторе модели:
«определять наведение» (`hover`) и «определять клик» (`click`).

Движок в игре пускает луч из камеры через курсор и проверяет его против
локального AABB модели (`model.bounds`) — поэтому попадание есть даже у
повёрнутой и масштабированной модели. События получают скрипты сцены через
`ctx.api.on(type, handler)` и `onEvent`:

| Событие | Когда | Поля |
|---------|-------|------|
| `pointer.hover` | курсор вошёл в модель (только при `hover: true`) | `id`, `entity`, `point` |
| `pointer.leave` | курсор вышел из модели | `id`, `entity` |
| `pointer.click` | ЛКМ по модели (только при `click: true`) | `id`, `entity`, `point`, `screen` |

```js
init(ctx) {
  ctx.api.on('pointer.hover', (event) => {
    if (event.id === ctx.entity.id) ctx.api.effects?.spark?.('hover', { position: event.point });
  });
}
```

Луч берётся из позиции камеры и направления курсора, так что перекрытие
невидимыми объектами не учитывается: проверяются только модели с включённым
флажком. Наведение сбрасывается при паузе, открытом меню и обзоре камеры.

### `primitive` — примитив

```json
{
  "id": "cube", "type": "primitive", "shape": "box", "size": [8, 8, 8],
  "position": [12, 3, -116], "spin": 0.06,
  "material": { "color": "#3d4757", "metal": 0.6, "specular": 1.1 },
  "body": { "kind": "static", "collider": { "shape": "box", "halfExtents": [4, 4, 4] } }
}
```

`shape`: `box`, `sphere`, `cylinder`, `wedge`. `size` — габариты; для сферы это
диаметры, для цилиндра `[диаметр, диаметр, длина]` (ось Z).

Материал: `color`, `tint`, `emissive`, `metal` (0…1), `specular`.
`blend: "additive"` и `depthWrite: false` дают светящиеся ядра и стёкла.
`glow: { color, size, intensity }` добавляет мягкий билборд-ореол вокруг центра.

### `trigger` — объём с событиями

```json
{
  "id": "trigger-dock", "type": "trigger",
  "position": [0, 0, -60],
  "trigger": { "shape": "box", "size": [18, 10, 18], "once": true, "tag": "dock" },
  "scripts": ["doors/door-open.js"]
}
```

Каждый кадр рантайм проверяет, внутри ли корабль, и рассылает события
`trigger.enter` / `trigger.exit` скриптам сцены. Событие содержит `trigger` (id),
`tag` и `time`.

### `spawn` — точка появления

```json
{ "id": "spawn-start", "type": "spawn", "position": [0, 0, 20], "rotation": [0, 180, 0] }
```

`player.spawn` ссылается на такую сущность. Для ботов будут `spawn.for: "bot"`.

### `bot` — бот

```json
{
  "id": "bot-1", "type": "bot", "asset": "spaceship",
  "position": [-8, 2, -34],
  "bot": { "archetype": "patrol", "brain": "bots/patrol.js", "radius": 14, "speed": 0.35 },
  "scripts": ["bots/patrol.js"]
}
```

Бот — обычная сущность с моделью и скриптом поведения. Готовый скрипт
[`bots/patrol.js`](../public/scripts/bots/patrol.js) водит его по кругу
радиусом `bot.radius` со скоростью `bot.speed` рад/с и покачивает на `bot.height`.
Нос разворачивается по направлению движения через `api.faceDirection`.

Атакующее поведение — скрипт [`bots/aim-attack.js`](../public/scripts/bots/aim-attack.js):
бот ищет игрока в конусе обзора, наводится и стреляет снарядами из префаба.
Готовый префаб — `public/prefabs/bot.json`, описание и параметры —
[`docs/bots.md`](bots.md). Демо-сцена — `?scene=bots-demo`.

Своё поведение — это просто другой скрипт: получает `ctx.entity`, позицию,
`api.find`, `api.ship`.

### `camera` — камера сцены

```json
{
  "id": "camera-main", "type": "camera", "name": "Камера",
  "scripts": [{
    "file": "camera.js",
    "params": {
      "body": "corinth-cargo-ship-1", "height": 20, "distance": 120,
      "drop": 0, "tilt": 0, "fov": 55, "lag": 6
    }
  }]
}
```

Объект-камера — якорь для скрипта `camera.js`: в редакторе виден жёлтым конусом,
а всю логику движения задаёт скрипт. `body` — ссылка на сущность корабля
(её `id`), `height` / `distance` / `drop` / `tilt` / `fov` / `lag` — параметры обзора.
Скрипт каждый кадр считает позицию и точку взгляда, сглаживает их по `lag`
и отдаёт движку через `ctx.api.camera.setPose()`; встроенный облёт при этом
уступает скрипту. Наклон считается вокруг правого вектора корабля, выведенного
из его `forwardVector`.

Поля `camera` у сущности: `background` — цвет фона кадра (`#rrggbb`), `fov` / `near` / `far` — объектив. `background` применяется движком; остальные поля нужны для маркера и обратной совместимости, если камерой управляет скрипт. Если скрипта в сцене нет, движок берёт параметры первой видимой камеры.
Без камеры в сцене кадр не рисуется вообще: остаётся только фон сцены (по умолчанию чёрный) — собственных значений камеры у движка нет.

### `empty` — пустой узел

```json
{
  "id": "turret", "type": "empty", "name": "Турель",
  "position": [30, 0, 0], "rotation": [0, 45, 0],
  "scripts": ["rotator.js"],
  "children": [
    { "id": "turret-body", "type": "model", "asset": "sample-crate", "position": [0, 1.5, 0] },
    { "id": "turret-pivot", "type": "empty", "position": [0, 0, 3], "scripts": ["rotator.js"] }
  ]
}
```

Узел без геометрии: только трансформ и скрипты. Всё, что лежит в `children`,
едет и вращается вместе с ним — удобно собрать турель, шлюз или платформу
и повесить один скрипт на группу. Дети могут быть любыми сущностями и
вкладываться дальше; их `position`, `rotation` и `scale` считаются в осях
родителя. Скрипты на узле работают так же, как на модели: `ctx.entity` — это
сам узел, а `api.find(id)` находит и детей.

Ограничение: динамическое тело (`body.kind: "dynamic"`) внутри группы нельзя —
физика считает мировые координаты, а трансформ ребёнка локальный. Такие тела
держите на верхнем уровне. Статические коллайдеры у детей поддерживаются:
тело встаёт по мировой матрице и каждый кадр едет за родителем — жёсткая связь
без люфта и догоняния.

### `skybox` — небесная сфера

```json
{ "id": "skybox-1", "type": "skybox", "skybox": "alien-nebula-1" }
```

`skybox` — id из `public/skyboxes/index.json`. Пять панорам собираются
скриптом `tools/build-skyboxes.py` из исходников в `assets/`.

Небо рисуется **кубемапой**, а не equirect-картинкой: у неё нет шва на
азимуте склейки и нет растяжения у полюсов. На выходе сборки для каждой
панорамы лежат:

* `public/skyboxes/cube/<id>-{px,nx,py,ny,pz,nz}.jpg` — шесть граней
  (1024 px, у реалистичной — 2048 px);
* `public/skyboxes/<id>.jpg` — превью 2048×1024 для редактора;
* `public/skyboxes/<id>-thumb.jpg` — миниатюра для списка.

Панорама `realistic-milkyway` — реальный снимок ESO/S. Brunier (CC BY 4.0);
из него удалены точечные звёзды, остались только газ и пыль Млечного Пути.

* применяется **только один** skybox на сцену: если их несколько, берётся
  первый видимый;
* у сущности нет тела, коллайдера, добычи и участия в пикинге — `body`
  игнорируется;
* `position`/`rotation`/`scale` не используются: сфера всегда вокруг камеры,
  поэтому skybox обычно кладут в префаб игрока — «едет» с ним сам.

## Тела и коллайдеры

```json
"body": {
  "kind": "static",
  "collider": { "shape": "sphere", "radius": 9.36 },
  "restitution": 0.55,
  "friction": 0.2
}
```

| `collider.shape` | Поля |
|------------------|------|
| `sphere` | `radius`, `offset: [x, y, z]` |
| `box` | `halfExtents: [x, y, z]`, `offset: [x, y, z]` |
| `compound` | `spheres: [{ offset, radius }]`, `boxes: [{ offset, halfExtents }]` |

`kind: "dynamic"` + `mass` делает объект подвижным. Если `collider` не задан,
радиус берётся из габаритов модели.

Размеры коллайдера (`radius`, `halfExtents`, `offset`, `spheres`, `boxes`) задаются в локальных
единицах и умножаются на масштаб сущности — так же, как радиус триггера.
Модель, уменьшенная до `scale: 0.2`, получает и коллайдер в пять раз меньше.

## Эффекты

VFX-эффект можно прикрепить к любой сущности массивом `effects` или сделать
самостоятельным узлом `type: "effect"`. Описание эффекта лежит в
`public/effects/<id>.effect.json` и содержит `params`-схему и слои (`smoke`,
`spark`, ...).

```json
{
  "id": "ship-trail",
  "type": "model",
  "asset": "corinth",
  "effects": [{
    "id": "trail",
    "effect": "smoke-trail",
    "trigger": "auto",
    "loop": true,
    "duration": 1.2,
    "offset": [0, 0, 4],
    "rotation": [0, 0, 0],
    "scale": 1,
    "params": { "rate": 45, "color": "#8b93a3" }
  }]
}
```

Слот эффекта:

| Поле | Что означает |
|------|--------------|
| `id` | идентификатор слота внутри сущности |
| `effect` | id ассета или встроенное описание |
| `trigger` | `auto` / `manual` / `impact` / `trigger.enter` / `trigger.exit` |
| `loop` | повторять цикл |
| `duration` | длительность одного цикла, с |
| `offset`, `rotation`, `scale` | локальное положение относительно сущности |
| `params` | переопределение параметров из инспектора |

Узел `type: "effect"` — тот же слот, но у него есть собственный трансформ и
дети, поэтому его можно двигать гизмо и сохранять в префаб.

Runtime API скриптов: `ctx.api.effects.spawn(...)`, `play(...)`, `stop(...)`,
`setParams(...)`, `isActive(...)`. Старые `beam`, `tracer`, `rocket`, `smoke`,
`spark` остаются.

## Скрипты (следующий этап)

```json
"scripts": ["scripts/spin.js"],
"partScripts": { "group2 polySurface219": ["scripts/glow.js"] }
```

Скрипт — ES-модуль с хуками `init`, `update`, `onEvent`, `dispose`.
Имена мешей берутся из групп модели (`public/models/*.json` → `groups[].name`).

## Скрипты

Скрипт — обычный ES-модуль в `public/scripts`. Он получает контекст и живёт
до конца сцены:

```js
// public/scripts/rotator.js
export default {
  init(ctx) {},            // один раз при загрузке сцены
  update(ctx, dt) {},      // каждый кадр, пока игра не на паузе
  onEvent(ctx, event) {},  // события триггеров
  dispose(ctx) {}          // при выгрузке сцены
};
```

`ctx = { entity, part, scene, state, api }`:

| Поле | Что даёт |
|------|----------|
| `entity` | сущность сцены: `position`, `quaternion`, `body`, `raw` |
| `part` | имя меша, если скрипт висит на детали модели |
| `state` | личные данные экземпляра — одно поведение на разных объектах не делит переменные |
| `api.find(id)` | другая сущность сцены |
| `api.move(entity, [dx,dy,dz])` | сдвинуть |
| `api.setPosition(entity, [x,y,z])` | поставить в точку |
| `api.rotate(entity, axis, angle)` | довернуть |
| `api.impulse(entity, [x,y,z])` | толкнуть физическое тело |
| `api.on(type, fn)` / `api.emit(event)` | свои события |
| `api.ship` | состояние корабля игрока (`pos`, `vel`, `quat`) |

Привязка в сцене:

```json
"scripts": ["doors/door-open.js"],
"partScripts": { "group2 polySurface219": ["scripts/glow.js"] }
```

`partScripts` вешает поведение на отдельный меш модели — имя берётся из
`groups[].name` в `public/models/<id>.json`.

### Событие попадания снаряда

Когда снаряд попадает в тело, система снарядов отправляет событие
`projectile.hit`. Его видят и `ctx.api.on`, и хук `onEvent` любого скрипта:

```js
ctx.api.on('projectile.hit', (event) => {
  // event.entity — сущность цели (может быть null)
  // event.body, event.point, event.normal, event.direction,
  // event.speed, event.projectile — id префаба снаряда
});
```

Событие приходит один раз на снаряд, после эффекта `impact` и импульса телу.
Снаряды кинематические, поэтому событий физики (`impact`) от них нет — только
это.

Готовые примеры: [`public/scripts/rotator.js`](../public/scripts/rotator.js) —
вращение, [`public/scripts/doors/door-open.js`](../public/scripts/doors/door-open.js) —
дверь по триггеру.

## Импорт моделей (GLB)

В редакторе есть кнопка **«Импорт GLB»**: выберите файл `.glb` — редактор
разберёт его прямо в браузере, соберёт наш ассет и положит его в `public/models`.

Что делает импорт:

* читает контейнер GLB (JSON + бинарный чанк) и все accessor'ы, включая interleaved;
* запекает иерархию узлов (TRS/матрицы) в вершины и нормали — в сцене модель стоит целиком;
* переносит материалы: `baseColorFactor` → цвет, `metallicFactor` / `roughnessFactor` → металл и блик,
  `emissiveFactor` → свечение;
* пишет `<id>.json` + `<id>.mesh.bin` в том же формате, что Corinth и астероиды
  (раскладка `[позиции][нормали][UV][индексы]`, всё по 4 байта).

Ограничения текущей версии: текстуры из GLB не переносятся (цвет берётся из материала),
скины и анимации не поддерживаются, только треугольные примитивы.

Сгенерировать тестовую модель для проверки:

```powershell
node tools/make-test-glb.mjs   # assets/import/sample-crate.glb
```

Серверные ручки:

| Метод | Адрес | Что делает |
|-------|-------|------------|
| GET | `/api/assets` | список ассетов в `public/models` |
| POST | `/api/asset/<id>` | сохранить ассет: `{ manifest, binBase64 }` |

## HUD из сцены

Интерфейс — это HTML-слои поверх canvas. Движок не расставляет их по экрану:
он только вставляет HTML в контейнер сцены `#scene-hud`. Контейнер прижат к правому
верхнему углу, слои идут колонкой — поэтому «по умолчанию всё вверху справа».

```json
{ "id": "hud-keys", "type": "hud", "name": "Клавиши", "hud": { "file": "hud/keys.html" } }
```

| Поле | Смысл |
|------|-------|
| `hud.file` | HTML-файл из `public/hud` |
| `hud.bind` | `model` — подставить имя модели корабля |
| `hud.startHidden` | `true` — слой скрыт до вызова из скрипта |

Положение и вид задаёт сам HTML/CSS: если файлу нужно занять весь экран или встать
вниз — это делается правилами в стилях сцены (`hud/style.css`). Поле `position`
больше не используется. А вот `hud.follow`, `hud.anchor`, `hud.offset` и `hud.scale`
работают — но только у привязанных слоёв (см. ниже).

Слои идут в порядке дерева и просто накладываются друг на друга. Если в сцене
есть хотя бы один слой, встроенные блоки интерфейса (логотип, подсказки, клавиши)
движок убирает — статику задаёт сцена. Динамика оружия и добычи живёт
в скриптах сцены; встроенных панелей в движке больше нет.

### Привязка к объекту

Без привязки слой просто вставляется в контейнер сцены и идёт обычным блоком
страницы — от левого верхнего края.
Если нужна подпись над объектом — задайте `hud.follow`:

| `hud.follow` | Что делает |
|--------------|------------|
| `none` | без привязки, в контейнере сцены |
| `parent` | едет за родительским объектом — слой должен быть его ребёнком |
| `entity` | едет за объектом из `hud.target` |
| `target` | едет за маркером цели |

У привязанного слоя работают `hud.anchor` (какая точка садится в координату),
`hud.offset` (сдвиг в пикселях) и `hud.scale`. Если объект за камерой или вне
кадра, слой скрывается. Так сделана подпись станции: слой `hud-station-label`
лежит внутри модели станции с `follow: parent` и `offset: [0, -70]`.

### Стили HUD

HTML-слои вставляются в общий контейнер `#scene-hud`. Внешний вид HUD живёт
в **одном файле стилей сцены** из корневого объекта; в `public/style.css` остаётся
только каркас движка (canvas, сам контейнер, загрузочный экран). Стили самих слоёв
(`.hud-layer`, `.attached`, `.offscreen`) тоже лежат в файле сцены:

```json
{ "id": "scene", "type": "scene", "hud": { "style": "hud/style.css" } }
```

Движок подключает его один раз при загрузке сцены (`<link id="scene-hud-style">`),
поэтому правила сразу действуют на все слои — отдельные CSS для каждого HUD не
нужны. Путь — только внутри `public/hud` (`hud/...css`), иначе поле игнорируется.

### Загрузочный экран

Пока сцена грузится, движок показывает экран из объекта «Сцена»:

```json
"loading": { "file": "hud/loading.html", "script": "scripts/loading.js" }
```

HTML вставляется в `#overlay`, скрипт — обычный модуль с `init(ctx)` / `update(ctx, dt)` /
`dispose(ctx)`; цикл тот же, что у игры (кадры `requestAnimationFrame`). Скрипт получает:

| API | Что даёт |
|-----|----------|
| `api.loading.getProgress()` | прогресс загрузки, 0…1 |
| `api.loading.getElapsed()` | секунды с начала загрузки |
| `api.loading.isReady()` | сцена готова, экран сейчас уйдёт |
| `api.loading.getError()` | текст ошибки или `null` |
| `api.root` | элемент `#overlay`, внутри него HTML экрана |

Прогресс движок обновляет по этапам: чтение сцены, сборка объектов (по одному),
HUD, скрипты, готово. Если HTML или скрипт не загрузились, остаётся встроенная
заглушка с процентом и временем. Редактируется в инспекторе объекта «Сцена».

### Скрытые слои

```js
ctx.api.hud.show('hud-menu');    // показать
ctx.api.hud.hide('hud-menu');    // скрыть
ctx.api.hud.toggle('hud-menu');  // переключить
ctx.api.hud.isVisible('hud-menu');
ctx.api.hud.exists('hud-menu');
```

Пример с меню: слой `hud-menu` (`hud/menu.html`, `startHidden: true`) и
`input.js` на игроке. Скрипт забирает Esc подсистемой `pause` и по нажатию
делает `api.hud.toggle('hud-menu')`; встроенная пауза движка при этом молчит.
Если слоя `hud-menu` в сцене нет, Esc работает как раньше — открывает паузу.

Сырые клавиши скриптам доступны через `api.input.keysDown` (Set кодов вроде
`KeyW`, `Escape`), мышь — `api.input.mouse`, курсор — `api.input.cursor`.

Прицел и маркер цели — встроенные элементы движка, а не слои сцены: перекрестие
идёт за мышью, маркер — в точке прицела в 500 единицах по носу. Цель можно задать
кодом — `window.__galaxy.setTarget('asteroid1')` — её используют скрипты подсказок.

В редакторе: `+ HUD` добавляет слой; в инспекторе — только файл, подстановка
и «скрыт на старте». Положение и вид задаёт сам HTML/CSS слоя.

## Игрок

Отдельного поля «это корабль игрока» нет. Игрок — обычная сущность сцены,
на корне которой есть скрипт `input.js`; движок находит её сам и ничего не
создаёт. Готовый префаб — `public/prefabs/player-ship.json`: «пустой» узел с
телом `dynamic`, внутри модель, на узле `input/movement/rotation/weapon/extract`.

Сцена может быть и без игрока: тогда есть только камера, которая смотрит из
`player.position` и крутится мышью, а панели оружия и добычи скрыты.
`player.model` и `player.spawn` оставлены для совместимости и на новую схему
не влияют.

Когда сцена собрана и `init` всех скриптов выполнен, страница сообщает движку:
`window.__galaxy.ready = true` и событие `galaxy:scene-ready` с `detail`
`{ id, entities, player }`. До этого момента управление не включается.

## Переменные скриптов

Скрипт может объявить схему своих параметров, и редактор нарисует по ней поля
в инспекторе. Значения хранятся в сцене рядом со скриптом:

```js
// public/scripts/camera.js
export const params = {
  body: { label: 'Корабль', default: 'ship', type: 'entity' },
  height: { label: 'высота камеры', default: 20, min: 0, max: 200, step: 1 },
  distance: { label: 'дистанция', default: 120, min: 0, max: 120, step: 1 },
  fov: { label: 'угол обзора', default: 55, min: 5, max: 120, step: 1 }
};
```

```json
"scripts": [
  {
    "file": "camera.js",
    "params": { "body": "corinth-cargo-ship-1", "height": 20, "distance": 120, "fov": 55 }
  }
]
```

В скрипте значения приходят в `ctx.params` (недостающие берутся из `default`).
`type: 'entity'` рисует в инспекторе выпадающий список сущностей сцены: значение —
`id` выбранного объекта, вложенные узлы показаны с отступами. Если ссылка ведёт
на удалённый объект, редактор показывает её как «нет в сцене», а скрипт может
подстраховаться через `ctx.api.player`.

В редакторе: выделить объект → секция «Скрипты» → поля скрипта.

## Камера и меню

Камера живёт в скрипте `camera.js`, который вешается на объект `camera`.
Скрипт забирает подсистему `api.claim('camera')` и каждый кадр сам считает позу:

* `body` — ссылка на сущность корабля (`id`), у неё берутся мировая позиция и поворот;
* `height` — смещение по Up корабля;
* `distance` — по Back (за кормой);
* `side` — по Right (плечо);
* `drop` — насколько точка взгляда поднята по Up: на столько корабль опущен
  от центра экрана;
* `tilt` — поворот всей связки вокруг правого вектора корабля, выведенного из
  его `forwardVector`; 0…360°;
* `fov` — угол обзора, `lag` — плавность (экспоненциальное сглаживание позиции
  и точки взгляда).

Готовая поза отдаётся движку:

```js
ctx.api.camera.setPose({
  position: [x, y, z],
  lookAt: [x, y, z],
  up: [0, 1, 0],
  fov: 55
});
```

Пока скрипт владеет камерой, встроенный облёт движка не применяется — рендер
берёт `position` / `lookAt` / `up` / `fov` из последней позы скрипта.
`ctx.api.camera.clearPose()` возвращает управление движку.

Слайдеры меню (`hud/menu.html`) читаются скриптом каждый кадр: «Высота камеры»
0–200, «Дистанция камеры» 0–120, «Корабль ниже центра» 0–15, «Наклон камеры»
0–360°. Значения из сцены сразу выставляются в контролы при `init`.

Меню — это слой `hud-menu` с разметкой панели паузы; если он есть в сцене,
движок убирает свою встроенную панель, а `input.js` забирает Esc. Пока меню
открыто, `entity.controls.blocked = true`: корабль не получает тягу и не
поворачивает по курсору, стрельба и луч выключены, но скорость живёт обычной
жизнью — инерция и торможение идут ровно так же, как без меню.

## Скрипты игрока и подсистемы

Скрипт может забрать подсистему у движка вызовом `api.claim(name)`:

| `name` | Что перестаёт делать движок |
|--------|-----------------------------|
| `movement` | тяга, торможение и предел скорости |
| `rotation` | доворот корабля к прицелу и крен |
| `weapons` | движкового оружия больше нет — стрельбу ведёт `weapons.js` |
| `mining` | движковой добычи больше нет — луч и прогресс ведёт `mining.js` |

Если подсистему никто не забрал, работает прежняя логика движка — старые сцены
без скриптов ведут себя как раньше. Дополнительно у скриптов есть `api.player`,
`api.input` (`keys`, `cursor`, `mouse`, `keysDown`, `cursorRay()`),
`api.aimQuaternion()`, `api.aimTarget()`, `api.miningTargets()`,
`api.setVelocity / getVelocity / setQuaternion / setPosition`, а также
`api.effects` (`beam`, `tracer`, `rocket`, `smoke`, `spark`) и `api.hud`
(`setText`, `setClass`, `setStyle`, `onClick`).

## Префабы

Префаб — сохранённая ветка сцены: объект вместе со всеми детьми, материалами
и скриптами. Лежит в `public/prefabs/<id>.json` и вставляется в любую сцену.

```json
{
  "version": 1,
  "id": "turret",
  "title": "Турель",
  "entities": [
    {
      "id": "empty-1", "type": "empty", "name": "Турель",
      "position": [30, 0, 0], "scripts": ["rotator.js"],
      "children": [
        { "id": "sample-crate-1", "type": "model", "asset": "sample-crate" }
      ]
    }
  ]
}
```

В редакторе: выделите объект (можно группу с детьми) → «В префаб» → имя.
Вставка: выберите префаб в списке → «Вставить». Префаб появляется в точке
камеры, а если выбрана группа — внутрь неё. `×` рядом со списком удаляет
префаб из `public/prefabs`.

При вставке все `id` перенумеровываются, поэтому один префаб можно ставить
сколько угодно раз. Скрипты и вложенность сохраняются, но скрипт, который
ищет объект по жёсткому id внутри префаба (`api.find('door-1')`), после
вставки его не найдёт — обращайтесь к детям через `ctx.entity.children`
или к самому узлу через `ctx.entity`.

При сохранении префаб чинится: ссылки скриптов (`body`, `muzzleLeft`, `origin`…),
`hud.target`, `bot.spawn` и `spawnId` на объекты **вне** сохраняемой ветки и на
несуществующие id очищаются, внутренние остаются и перенумеруются при вставке.
Поэтому префаб самодостаточен, а внешние привязки вроде «корпус игрока» лучше
не хранить жёстко — скрипты и так падают обратно на `ctx.api.player`.

### Редактирование префаба

Выберите префаб в списке → **«Редактировать»**. Откроется отдельное окно
`editor.html?prefab=<id>`: тот же редактор, но в документе только этот префаб,
без surrounding-сцены. Дерево, инспектор, гизмо, добавление объектов и
скриптов работают как обычно; сохранение пишет `public/prefabs/<id>.json`.
Кнопки сцены (выбор сцены, «Играть», откат) в этом режиме скрыты.

API: `GET /api/prefabs` — список, `GET /api/prefab/<id>` — файл,
`POST /api/prefab/<id>` — сохранить, `DELETE /api/prefab/<id>` — удалить.

### Снаряд из префаба

Если у корня префаба есть блок `projectile`, префаб считается снарядом.
Рантайм собирает его без физического тела: положение ведёт свип, а не
решатель контактов. Дети настраиваются как обычно; тела у них тоже не
создаются.

| Поле | Тип | По умолчанию | Что задаёт |
|------|-----|--------------|------------|
| `speed` | number | 95 | скорость полёта, м/с (10…1000) |
| `life` | number | 6 | время жизни, с (0.5…30) |
| `radius` | number | 0.4 | радиус свип-сферы, м (0.05…5) |
| `turnRate` | number | 0 | запас на самонаведение, рад/с (пока не используется) |
| `damage` | number | 0 | урон для будущей системы HP |
| `impulse` | number | 0 | импульс телу цели в точке попадания |
| `impact` | string \| null | null | id эффекта из `public/effects` в точке попадания |
| `trail` | string \| null | null | id эффекта-следа; у ракеты — `smoke-trail` |

След удобно держать слотом на корне префаба — тогда пул включает его при
выстреле и гасит при возврате:

```json
"effects": [
  { "id": "trail", "effect": "smoke-trail", "trigger": "manual",
    "offset": [0, 0, 1.25], "loop": true }
]
```

Модель ракеты смотрит носом в **−Z**: кватернион полёта строится
из направления `[0, 0, -1]`.

Выстрел из скрипта:

```js
ctx.api.projectiles.fire({
  prefab: 'rocket',
  from: muzzle,
  direction,
  owner: ctx.api.find(ctx.params.body)
});
```

`ctx.api.projectiles.stats()` отдаёт `{ fired, hits, expired, rejected, size, free, active }`.

## Редактор

Откройте <http://localhost:3000/editor.html> (или `editor.html?scene=<id>`).
Редактор работает на том же рантайме, что и игра, и сохраняет файлы прямо в проект.

| Что делает | Как |
|------------|-----|
| Выбрать объект | клик по строке в дереве слева; клики по вьюпорту объект не выбирают |
| Двигать по одной оси | потянуть за цветную ось (X — красная, Y — зелёная, Z — синяя) |
| Двигать свободно | потянуть сам объект — он едет в плоскости взгляда |
| Масштаб мышкой | `S` — гизмо масштаба: тяните ось (меняется одна ось) или центр (равномерно) |
| Вращение мышкой | `R` — кольца вокруг осей: тяните кольцо, объект крутится вокруг этой оси |
| Вращать / масштабировать | поля `поворот°` и `масштаб` в инспекторе |
| Вращать камеру | ЛКМ по пустому месту |
| Приблизить | колесо мыши |
| Панорама | ПКМ или средняя кнопка |
| Добавить пустой узел | `+ Пустой` — группа без геометрии: трансформ и скрипты, внутрь кладутся модель или другой пустой |
| Добавить камеру | `+ Камера` — объект с `fov` / `near` / `far`, в сцене рисуется жёлтым конусом обзора |
| Положить объект внутрь | перетащите строку в дереве на строку пустого узла; на обычную строку — встанет следом за ней, на пустое место — вернётся в корень |
| Добавить триггер | `+ Триггер` |
| Спавн и бот | кнопок добавления нет; существующие объекты `spawn` / `bot` в сцене по-прежнему выбираются и редактируются |
| Подключить скрипт | секция «Скрипты» в инспекторе: выбрать файл → «Добавить скрипт» |
| Сохранить префаб | выделить объект → «В префаб» → имя; ветка с детьми уходит в `public/prefabs/<id>.json` |
| Редактировать префаб | выбрать префаб → «Редактировать» — отдельное окно `editor.html?prefab=<id>`, только этот префаб |
| Контекстное меню | правый клик по строке дерева: «Создать префаб» или «Редактировать префаб», затем «Добавить пустой / HUD / триггер / камеру»; правый клик по пустому месту левой панели — те же добавления (двойной клик по строке-префабу сразу открывает его редактор) |
| Добавить префаб | контекстное меню → «Добавить префаб» → выбрать префаб в диалоге → «Вставить»; ветка появится в сцене и в списке объектов |
| Селект префабов в шапке | отдельная группа: выбрать префаб и нажать «Редактировать префаб» |
| Вставить префаб | выбрать в списке префабов → «Вставить» (в точку камеры или внутрь выбранной группы) |
| Удалить префаб | `×` рядом со списком префабов |
| Дублировать / удалить | `Ctrl+D` / `Delete` |
| Скрыть из игры | кнопка-глаз в строке дерева или галочка «в игре» в инспекторе; скрытый объект и его дети не строятся в игре, но остаются в сцене |
| Сохранить | `Ctrl+S` или кнопка «Сохранить» |
| Откатить | кнопка «Откат» — вернуть предыдущую версию файла |
| Автосохранение | галочка «авто» — сохраняет через 1.5 с после правки |
| Импортировать модель | «Импорт GLB» → выбрать `.glb` — модель появится в центре камеры |

Инспектор правит трансформ, материал, массу, отскок и простой коллайдер (радиус
сферы или полуразмеры бокса). Состав compound собирается в редакторе модели,
а в инспекторе показывается только число его частей. Галочки сверху показывают
сетку и коллайдеры: сферы рисуются каркасной сеткой из меридианов и параллелей,
боксы (в том числе части compound) — рёбрами.
Это чистые линии без заливки и текстур, поэтому объём видно, а картинка не перекрывается.

Три режима гизмо — кнопки в левом верхнем углу вьюпорта или клавиши: **G** — перемещение, **R** — вращение,
**S** — масштаб. В каждом режиме мышь делает только своё: в перемещении объект едет,
в вращении крутятся только кольца, в масштабе меняется только размер.

Сохранение идёт через `POST /api/scene/<id>`; сервер принимает его только
с этого компьютера и пишет файл в `public/scenes/<id>.scene.json` с отступами.

Что видно при сохранении:

* рядом с кнопкой индикатор: «без изменений» / «● не сохранено» / «Сохранено…» / «сохранено 20:04»;
* кнопка блокируется на время записи, повторные клики не плодят запросы;
* после записи редактор перечитывает файл и сверяет число сущностей — если на диске
  не то, что отправили, будет ошибка, а не молчаливое «Сохранено»;* в статусе пишется время, число сущностей и напоминание обновить вкладку игры (F5);
  ссылка «Играть ↗» всегда открывает свежую копию (с меткой времени).

Если файл сцены успели изменить в другой вкладке, сохранение вернёт конфликт: редактор
предложит загрузить версию с диска, а не перезапишет чужие правки молча.

Если есть несохранённые изменения, редактор спросит подтверждение при смене
сцены и при закрытии вкладки.

Перед записью сервер кладёт предыдущую версию в `<id>.scene.json.bak` —
кнопка «Откат» возвращает её (только последняя версия). Пустую сцену
(без сущностей) сервер не сохраняет.

### API (только localhost)

| Метод | Адрес | Что делает |
|-------|-------|------------|
| GET | `/api/scenes` | список сцен |
| GET | `/api/scene/<id>` | JSON сцены |
| POST | `/api/scene/<id>` | сохранить сцену (с бэкапом) |
| POST | `/api/scene/<id>/restore` | откатить к `.bak` |
| GET | `/api/scripts` | список скриптов в `public/scripts` |

## Проверка сцены

```powershell
npm test
```

Тесты физики и добычи не зависят от сцены. Ошибку в JSON видно сразу: загрузчик
бросает исключение с путём до проблемного поля, например
`entities[2].body.collider: у сферы коллайдера нужен radius > 0`.
