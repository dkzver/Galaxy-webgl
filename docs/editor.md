# Редактор сцен и префабов

Редактор один: `public/editor.html` + `public/js/editor/editor.js`. Режим задаётся адресом:

```
editor.html?scene=first-game     # сцена
editor.html?prefab=player-ship   # префаб — тот же файл, только дерево другое
```

## Правило

**Правка редактора должна работать сразу в обоих режимах — сцены и префаба.**
Это одни и те же файлы и одна логика; отличаться может только поведение, зависящее
от `state.mode` (`scene` / `prefab`). Нельзя заводить отдельную копию разметки или
скрипта под префаб: иначе окна разъедутся, и правка в одном не попадёт в другое.

Если меняешь разметку, стили или логику редактора — проверь оба адреса выше.

## Каркас окна

| Часть | Класс | Что внутри |
|-------|-------|------------|
| шапка | `.editor-header` | бренд, выбор сцены, сохранение/откат, кнопки добавления, префабы, «Играть» |
| левый бар | `.editor-left` | дерево объектов (в сцене первым идёт «Сцена») |
| центр | `.editor-center` | canvas с 3D, гизмо, режимы, превью HUD |
| правый бар | `.editor-right` | инспектор выбранного объекта или объекта «Сцена» (фон, стили HUD, загрузочный экран, модель игрока) |
| статус | `.editor-status` | сообщения, число сущностей, дистанция камеры |

Сетка задаётся в `public/editor.css` (`.editor`), части размечены `grid-area`.

## HUD в редакторе

Превью HUD живёт в изолированном `<iframe id="hud-preview">` внутри центральной
части. Внутрь фрейма подключаются `editor.css` и стили сцены из объекта «Сцена»
(`hud.style`), поэтому CSS слоёв HUD **не влияет** на интерфейс редактора.

Слои во фрейме — те же HTML-файлы из `public/hud`, что и в игре; позиционирование
не задаётся движком: контейнер `.hud-preview` внутри фрейма прижат к правому
верхнему углу, остальное — CSS слоя.

## Редактор модели

Отдельное окно: `model-editor.html?model=<id>`, открывается кнопкой
**«Редактировать модель»** рядом с «+ Модель» в шапке.

| Что | Откуда |
|-----|--------|
| Предпросмотр меша и коллайдера | WebGL-канвас: ЛКМ — поворот, клик по части — выбор; положение меняется только полями, мышью коллайдер не перетаскивается; колесо — масштаб |
| Габариты, длина, bounds, число групп | манифест `public/models/<id>.json` (справочно) |
| `static` / `dynamic`, масса | форма окна |
| Отскок, трение, коллайдер (`sphere` / `box` / `compound`) | форма окна; у `sphere`/`box` задаются радиус/полуразмеры и центр (`offset`), у compound — список частей (боксы и сферы); части выбираются кликом, но двигаются только полями центра — мышью не перетаскиваются |
| Автоколлайдер | «Построить по модели»: режим `боксы` / `сферы` / `гибрид`, детализация 8–48, лимит 1–32. Боксы — плотное покрытие корпуса, сферы — объём и скругления, гибрид смешивает их. «Упростить» сливает соседние боксы; результат сразу сохраняется |
| Ручная сборка | «+ бокс» / «+ сфера», поля центра и полуразмеров, двойной клик по корпусу добавляет бокс в точку попадания; Ctrl+Z отменяет, Delete удаляет выбранную часть |
| Добавить эффект | кнопка «+ Эффект» в шапке создаёт узел `type: "effect"` в выбранной группе; в дереве он помечен ✧, во вьюпорте — сфера привязки и направление |
| Прикрепить эффект к объекту | инспектор → «Эффекты» → выбрать ассет → «Прикрепить эффект»; настраиваются trigger, loop, duration, offset, scale и params |
| Тест эффекта | кнопка «▶ тест» в секции эффектов запускает инстанс в предпросмотре вьюпорта |
| Сменить меш | выберите объект модели/бота в дереве → инспектор → «Меш» → другая модель из `public/models`; объект пересоберётся, физика останется прежней |
| Сохранить эффект | сцена/префаб сохраняются как обычно; узлы `type: "effect"` и `entity.effects` попадают в JSON |
| Переимпорт меша | кнопка «Переимпортировать»: выбрать другой `.glb` — id и физика сохранятся |

## Эффекты

Описания лежат в `public/effects/<id>.effect.json`; список отдаёт
`GET /api/effects`, чтение/запись — `GET|POST /api/effect/<id>`. В инспекторе
эффект можно прикрепить к любому объекту (`entity.effects`) или создать
отдельный узел `type: "effect"`. Триггеры: `auto`, `manual`, `impact`,
`trigger.enter`, `trigger.exit`; `loop`/`duration` задают жизненный цикл,
`offset`/`scale` — привязку, `params` — переопределение цвета, частоты,
размера и т.п.

Runtime-инстансы живут в `EffectSystem`: auto-эффекты стартуют при сборке
сцены, impact — по событию физики, скрытый/удалённый родитель останавливает
эффект. Скрипты управляют ими через `ctx.api.effects.spawn/play/stop/setParams/isActive`.


Движок считает столкновения для compound из боксов и сфер: пары бокс-бокс, бокс-сфера и сфера-сфера. Поэтому автоколлайдер умеет строить как боксы, так и сферы/гибрид. Точного mesh-коллайдера в физике нет: части — воксельное приближение по треугольникам.

Как строится: меш растрируется в воксели (пересечение треугольник-воксель, без щелей на границах), заливка снаружи отделяет объём, микрощели закрываются локальным лучевым консенсусом (`sealGaps`, до 3 ячеек), затем жадное покрытие перебирает шесть порядков осей и собирает бруски. Сферы упаковываются по полю расстояний до внешнего пространства. Если частей больше лимита, сетка огрубляется и пересобирается; в строке статистики видно заполнение. Модули `public/js/editor/collider/*` не знают про DOM и проверяются тестами `tests/collider-fit.test.mjs`.

**Переимпорт** заменяет `models/<id>.json` и `<id>.mesh.bin` тем же id: сцены,
которые ссылаются на ассет, сразу рисуют новый меш. Физика (`<id>.physics.json`)
остаётся от старой версии — коллайдер стоит пересобрать. Старые наборы текстур
этого ассета, которых нет в новой версии, сервер удаляет.

Сохранение пишет `public/models/<id>.physics.json` (отдельный sidecar — сам меш и
манифест не трогаются). Эти значения подставляются, когда модель добавляют в
сцену через «+ Модель»; у уже добавленных объектов остаётся своя копия `body`,
которую правит инспектор сцены.
